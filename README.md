## Deployment

### Podman Compose

```yaml
services:
  crowdsec:
    image: "ghcr.io/daemonless/crowdsec:latest"
    container_name: crowdsec
    environment:
      - PUID=1000  # User ID for the application process
      - PGID=1000  # Group ID for the application process
      - TZ=UTC  # Timezone for the container
      # - COLLECTIONS=  # Space-separated CrowdSec Hub collections to install on startup (for example crowdsecurity/caddy crowdsecurity/nginx)
      # - PARSERS=  # Space-separated CrowdSec Hub parsers to install on startup
      # - SCENARIOS=  # Space-separated CrowdSec Hub scenarios to install on startup
      # - ENROLL_KEY=  # CrowdSec Console enrollment key
      # - ENROLL_INSTANCE_NAME=  # Instance name registered in CrowdSec Console when ENROLL_KEY is set
      # - ENROLL_TAGS=  # Space-separated tags passed to cscli console enroll
      # - POSTOVERFLOWS=  # Space-separated CrowdSec Hub postoverflows to install on startup
      # - APPSEC_CONFIGS=  # Space-separated CrowdSec AppSec WAF configs to install on startup
      # - APPSEC_RULES=  # Space-separated CrowdSec AppSec WAF rules to install on startup
      # - DISABLE_ONLINE_API=  # Disable Central API (CAPI) registration and community blocklist pulls
      # - DISABLE_AGENT=  # Run only the Local API (LAPI) and disable the log processor agent (-no-cs)
      # - NO_HUB_UPGRADE=  # Skip automatic CrowdSec Hub index updates and upgrades on startup
      # - CUSTOM_HOSTNAME=  # Machine name this instance registers with its Local API (default localhost)
      # - LOCAL_API_URL=  # Local API URL written to local_api_credentials.yaml for cscli and the agent (default http://127.0.0.1:8080)
    volumes:
      - "/containers/crowdsec:/config"
    ports:
      - "8080:8080"
    # always (not unless-stopped) so FreeBSD's podman rc.d auto-starts it at boot
    restart: always
```

Save as `compose.yaml`, then run `podman-compose up -d`.

## Storage layout and CLI

Configuration files (`/config/etc`) and the SQLite database plus downloaded
Hub data (`/config/data`) are persisted under `/config`. Inside the
container, `/usr/local/etc/crowdsec`, `/etc/crowdsec`, and
`/var/db/crowdsec/data` symlink into `/config`, so standard `cscli` commands
work without extra flags:

```sh
podman exec crowdsec cscli metrics
podman exec crowdsec cscli decisions list
```

## Log acquisition and collections

Mount target service logs read-only into the container, add acquisition
definitions under `/config/etc/acquis.d/*.yaml` (or edit
`/config/etc/acquis.yaml`), and list matching Hub collections in
`COLLECTIONS` (for example `crowdsecurity/nginx`, `crowdsecurity/caddy`,
or `crowdsecurity/haproxy`). For logs from another host or router (such
as OpenWRT or HAProxy), add a `source: syslog` listener under
`/config/etc/acquis.d/` with a `listen_port` above 1024 (the container
does not run as root) and publish that UDP port.

## Bouncers and firewall remediation

On FreeBSD or a router, a firewall bouncer
(`security/crowdsec-firewall-bouncer`, OPNsense plugin, or OpenWRT
firewall bouncer) connects to this container's LAPI on port `8080`.
Reverse-proxy and application bouncers (Caddy, nginx, HAProxy,
Cloudflare) connect to port `8080` the same way.

Register bouncers with `cscli bouncers add <name>` or pass
`BOUNCER_KEY_<name>=<api-key>` (or `BOUNCER_KEY_<name>_FILE=/path/to/key`)
to auto-register on startup.

## Optional ports

Publish `6060` for Prometheus `/metrics` or `7422` when enabling an AppSec
WAF listener in `/config/etc/acquis.d/`.
